## Entity Details

### Candidate — The Talent Graph Node

The candidate is the central entity. It stores **6 intelligence layers** that go far beyond a traditional resume database.

| Layer | Fields | Why it matters |
|---|---|---|
| **Identity** | name, email, phone, location, linkedinUrl, avatarUrl | Basic contact + reachability |
| **Experience** | `Experience[]` — company, title, dates, promoted flag | Career trajectory + velocity calculation |
| **Skills** | `Skill[]` — name, category, proficiency (1-5) | Matchable against Hiring DNA |
| **Impact** | arrInfluenced, revenueImpact, productsLaunched, usersImpacted | Evidence of outcomes, not just activity |
| **Leadership** | teamSize, hiringResponsibility, budgetOwnership, executiveExposure | Distinguishes managers from ICs |
| **Preferences** | compensationExpected, remotePreference, relocationOpen, noticePeriod | Eliminates mismatched candidates early |

**Computed fields (recalculated on save):**
- `careerVelocity` — promotion rate, tenure consistency, scope growth
- `profileCompleteness` — weighted % of filled fields (0-100)

---

### Role — With Hiring DNA

The role is not a job description. It's a **structured decomposition** of what the client actually needs.

| Field Group | Fields | Purpose |
|---|---|---|
| **Basics** | title, level, department, client, compensation range | Standard role info |
| **Must-Haves** | mustHaveSkills[], experienceMin/Max, impactThreshold | Hard filter criteria — candidate MUST match |
| **Nice-to-Haves** | niceToHaveSkills[], industryPreference[] | Soft scoring criteria — bonus points |
| **Anti-Patterns** | antiPatterns[] | Red flags to avoid (e.g., "job-hopper <18mo") |
| **Context** | teamContext, successCriteria, cultureFit, leadershipSignal | Qualitative fit — recruiter uses for evaluation |
| **Operations** | status, publishedToNetwork, maxShortlist, feePercentage, slaDeadline | Pipeline and business rules |

**State machine:**

```
DISCOVERY ──▶ ACTIVE ──▶ SHORTLISTING ──▶ INTERVIEWING ──▶ OFFER ──▶ PLACED
    │                                                                    │
    ▼                                                                    ▼
CANCELLED                                                          (Placement
                                                                    created)
```

---

### CandidateScore — The Evaluation Record

One score per candidate per role. This is where matching happens.

| Dimension | Weight | What to assess |
|---|---|---|
| Role Fit (0-100) | 40% | Skill overlap with mustHaveSkills, experience depth, domain relevance |
| Evidence (0-100) | 25% | Verified impact vs role's impactThreshold (ARR, users, products) |
| Leadership (0-100) | 15% | Team management, hiring, budget — vs role's leadershipSignal |
| Trust (0-100) | 10% | Trust Graph signals — referrals, endorsements, "would hire again" |
| Evaluation (0-100) | 10% | Recruiter's gut after speaking to the candidate |

**Pipeline stages:**

```
SOURCED ──▶ SCREENED ──▶ EVALUATED ──▶ SHORTLISTED ──▶ INTERVIEWING ──▶ OFFERED ──▶ PLACED
   │            │             │              │                │             │
   ▼            ▼             ▼              ▼                ▼             ▼
REJECTED    REJECTED      REJECTED       REJECTED         REJECTED      DECLINED
```

---

### TrustEdge — The Trust Graph Edge

| Relationship | Direction | Weight | Signal strength |
|---|---|---|---|
| `REFERRED` | A→B | 3 | "I vouch for this person's work" |
| `WORKED_WITH` | A↔B (bidirectional) | 2 | "I've seen their work firsthand" |
| `MANAGED` | A→B | 4 | "I grew this person" |
| `MANAGED_BY` | A→B | 4 | "This person grew me" |
| `WOULD_HIRE_AGAIN` | A→B | 5 | **Strongest signal** — "I'd bet on them again" |

**Trust propagation (Phase 2):**

```
Direct trust:   A → B = weight * strength
Indirect trust: A → B → C = (A→B weight * B→C weight) * decay(0.3)

Max depth: 2 hops
Purpose: Discover candidates you don't know yet through trusted connections
```

---

### Referral — With Anti-Abuse Rules

| Rule | Enforcement | Error message |
|---|---|---|
| Max 3 per role per referrer | Count check before insert | "Maximum 3 referrals per role" |
| Cannot self-refer | Email comparison | "Cannot refer yourself" |
| Profile > 80% complete | Profile completeness check | "Complete your profile first (currently X%)" |
| First referrer gets credit | Unique check on candidateId+roleId | "This candidate has already been referred for this role" |
| 60-day cooling after rejection | Date check on rejectedAt | "This candidate is in a 60-day cooling period (until DATE)" |

**Scout Score:** `(submitted*1 + shortlisted*3 + interviewed*5 + hired*10) * max(hired/submitted, 0.1)`

**Talent Scout promotion:** scoutScore > 8.0 AND totalReferrals >= 5 AND hired >= 2

---

### Placement — Revenue Tracking

| Field | Purpose |
|---|---|
| actualCompensation | What the candidate actually received (may differ from role range) |
| feePercentage | Agreed fee % for this role |
| feeAmount | actualCompensation * feePercentage — the revenue |
| estimatedFee | What was projected at shortlist time (for accuracy tracking) |
| guaranteePeriod | 90 days — free replacement if candidate leaves |
| guaranteeExpiry | joinDate + 90 days |
| replacementNeeded | Triggered if candidate leaves within guarantee |

**States:** CONFIRMED → JOINED → PROBATION_PASSED (or REPLACEMENT_TRIGGERED)

### Candidates API

#### `GET /api/candidates`

List candidates with filtering and pagination.

**Query params:**

| Param | Type | Example |
|---|---|---|
| `search` | string | "Rahul product" (searches name, skills, company) |
| `skills` | string[] | "product-strategy,payments" |
| `status` | enum | "AVAILABLE" |
| `source` | enum | "REFERRAL" |
| `compensationMin` | number | 30 (LPA) |
| `compensationMax` | number | 80 (LPA) |
| `experienceMin` | number | 5 (years) |
| `experienceMax` | number | 12 (years) |
| `location` | string | "Bangalore" |
| `sortBy` | string | "compositeScore" / "careerVelocity" / "updatedAt" |
| `page` | number | 1 |
| `limit` | number | 20 |

**Response:**

```json

    {
      "id": "clx...",

      "compensationExpected": 55,
```

#### `POST /api/roles/[id]/match`

Run Hiring DNA against the Talent Graph. Returns candidates ranked by fit.

**Logic:**

```
1. Hard filter: mustHaveSkills overlap, experience range, compensation fit, location/remote, status
2. Soft rank: score remaining candidates on skill overlap, impact metrics, leadership match
3. Return top 20 with match reasons
```

**Response:**

```json
{
  "matches": [
    {
      "candidateId": "clx...",
      "name": "Rahul Sharma",
      "currentRole": "Senior PM @ Razorpay",
      "matchReasons": [
        "Has 3/3 must-have skills",
        "7 years experience (range: 5-10)",
        "ARR influenced: 150Cr (threshold: >10Cr)",
        "Team size: 8 (signal: 3+)"
      ],
      "missingNiceToHaves": ["International expansion"],
      "antiPatternFlags": [],
      "suggestedRoleFitScore": 85,
      "compensationFit": true,
      "locationFit": true
    }
  ],
  "totalMatches": 14,
  "filteredOut": 36,
  "filterReasons": {
    "missingMustHaveSkills": 18,
    "experienceOutOfRange": 8,
    "compensationMismatch": 6,
    "statusNotLooking": 4
  }
}
```

### Scoring API

#### `POST /api/scores`

Create or update a score.

```json
{
  "candidateId": "clx...",
  "roleId": "clx...",
  "roleFitScore": 85,
  "evidenceScore": 78,
  "leadershipScore": 70,
  "trustScore": 78,
  "evaluationScore": 80,
  "stage": "EVALUATED",
  "recruiterNotes": "Strong payments expertise. Deep experience with enterprise..."
}
```

**Side effects:**
- Auto-calculates `compositeScore = (85*0.4)+(78*0.25)+(70*0.15)+(78*0.1)+(80*0.1) = 80.3`
- Creates ActivityLog entry
- If stage changed, validates pipeline rules (e.g., max shortlist)

---

#### `PUT /api/scores/[id]/stage`

Move candidate to a new pipeline stage.

```json
{
  "stage": "SHORTLISTED"
}
```

**Validation:**
- If moving to SHORTLISTED: check `count(SHORTLISTED for this role) < role.maxShortlist`
- If moving to REJECTED: optionally include `rejectionReason`
- If moving to PLACED: trigger placement creation flow

## Key Computed Fields — Recalculation Triggers

| Field | Stored on | Recalculated when |
|---|---|---|
| `compositeScore` | CandidateScore | Any of the 5 dimension scores change |
| `careerVelocity` | Candidate | Experiences added/updated/deleted |
| `profileCompleteness` | Candidate | Any candidate field changes |
| `scoutScore` | User (referrer) | Any referral status changes |
| `isTalentScout` | User (referrer) | Scout score recalculated |
| `feeAmount` | Placement | actualCompensation or feePercentage changes |
| `guaranteeExpiry` | Placement | joinDate set/changed |
| `trustWeight` | TrustEdge | Relationship type changes |
